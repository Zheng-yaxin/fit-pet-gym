# ForgeFit OS 前端全站重构设计规格

## 背景

当前前端是 `Vue 3 + Vite` 项目，主要依赖包括 Element Plus、UnoCSS、ECharts、Pinia、vue-router 和 `lucide-vue-next`。现有界面里混合了 Apple glass、slate 管理台、原生 Element Plus 表格、局部自定义卡片等多种方向，整体不够统一，也没有形成足够鲜明的健身房产品识别。

本次确认采用的新方向是 **ForgeFit OS: 力场指挥舱**。它不继续参考旧界面，而是把产品重新定义为“健身房训练现场的运营指挥系统”：碳黑底、金属边、橡胶质感、高对比数据、能量色强调，以及有重量感、可打断、响应快的交互动效。

## 目标

- 将所有前端页面统一到一个新的视觉系统中。
- 让界面具有健身房主题、高级质感、强冲击力和专业运营感。
- 系统化处理导航、表格、表单、弹窗、图表、聊天、加载、空状态和错误状态。
- 建立可复用的 UI 基础组件，避免每个页面单独堆样式。
- 保留当前 Vue/Vite/Element Plus 技术栈，除非后续实现中有明确必要，不做 React 或 Next.js 迁移。
- 保证可访问性、键盘操作、移动端可读性和低动效模式。

## 非目标

- 不为了使用 shadcn/ui 而迁移技术栈。
- 不改后端 API 和业务模型。
- 不在视觉重构阶段随意改变业务流程。
- 不保留当前 Apple glass 或浅色 slate 作为主视觉。
- 不做纯装饰性、无交互意义的动画。

## 产品气质

ForgeFit OS 要传达五个关键词：

- **力量**：深色背景、强对比数字、硬朗控制面板。
- **精密**：网格严整、标签清晰、控件状态明确。
- **动能**：实时状态、进度反馈、操作有即时响应。
- **可信**：对比度充足、错误可恢复、危险操作有确认。
- **健身房身份**：训练数据、器械状态、课程容量、教练和会员关系、客流热力图都要成为视觉语言的一部分。

界面最终不应像通用 SaaS 后台，而应像高端健身房自己的运营系统。

## 视觉系统

### 主题名称

`ForgeFit OS`

### 核心隐喻

- 碳纤维和橡胶地垫作为大面积背景质感。
- 金属边线作为面板和控件的结构感。
- 能量条作为进度、激活态、完成态的视觉反馈。
- 训练计时器和性能仪表盘作为数据呈现参考。
- 热力图作为客流、人群密度和训练强度参考。
- 粉笔白文本保证深色背景下的清晰阅读。

所有组件使用语义 token，不在页面里重复写裸色值。

| `--ff-surface-muted` | `#292D25` | 次级控件 |
| `--ff-border` | `#343A30` | 默认边线 |
| `--ff-border-strong` | `#4A5244` | 聚焦和激活边线 |
| `--ff-text` | `#F3F1E8` | 主文本 |
| `--ff-text-secondary` | `#A7A99E` | 次文本 |
| `--ff-text-muted` | `#71766C` | 弱标签 |
| `--ff-accent-power` | `#B8FF2C` | 主操作、激活、完成、进度 |
| `--ff-accent-heat` | `#FF6A1A` | 热力、紧急、训练强度 |
| `--ff-accent-cool` | `#31D8C8` | 信息、连接、恢复状态 |
| `--ff-success` | `#6EEB83` | 成功 |

### 配色规则

- 以深色模式为基准设计。
- 绿色只用于能量、完成、激活和主操作，不能铺满全站。
- 橙色用于热力、强度、紧急和运营风险。
- 青色用于连接、数据、恢复和中性信息。
- 红色只用于危险、失败和不可逆操作。
- 所有主要文本、按钮、徽标和错误提示需要满足基本可读对比度。

## 字体系统

### 字体栈

- 中文和通用 UI：`Alibaba PuHuiTi`, `HarmonyOS Sans SC`, `Source Han Sans SC`, `Microsoft YaHei UI`, sans-serif。
- 数字和仪表盘：`Bahnschrift`, `DIN Alternate`, `Rajdhani`, `Arial Narrow`, sans-serif。

### 字体规则

- 桌面正文基础字号为 16px。
- 移动端正文不低于 14px。
- 仪表盘、表格、计时器、价格和数量统一使用 `font-variant-numeric: tabular-nums`。
- 全局不使用负字距。
- 大数字可以更粗、更窄，但说明文字必须保持易读。
- 中文文案要直接、短促、偏运营语言，避免营销腔。

## 布局系统

### 桌面端

- 后台使用固定左侧导航轨和高密度内容区。
- 主内容采用 12 栏网格，外边距 24px，模块间距 16px。
- Dashboard 使用整块操作带和独立面板，不做卡片套卡片。
- 表格页面要支持固定表头、紧凑行高、清晰操作列。

### 平板端

- 管理后台侧栏可收缩为图标轨。
- 表格重要列保持可见，横向滚动只发生在表格容器内部。
- 关键筛选条件优先展示，低频筛选收进折叠区。

### 移动端

- 会员端和教练端优先使用顶部上下文 + 底部导航。
- 管理后台在移动端使用抽屉导航。
- 主要触控目标不小于 44px。
- 关键操作不能只依赖 hover。

## 表面、形状和层级

- 默认圆角：8px。
- 小控件圆角：6px。
- 胶囊形只用于 badge、分段控件、紧凑筛选。
- 除移动端 sheet 外，避免 24px 或 32px 大圆角卡片。
- 用细边框、内高光和轻量层级表达高级感，不依赖厚重阴影。
- 不允许卡片套卡片。需要层级时，用标题、分隔线、行组、区域带来组织内容。

## 动效系统

### 动效气质

动效要像受控训练器械：快速、有重量、可中断、有因果关系。

### 时间 Token

| Token | 时长 | 用途 |
| --- | ---: | --- |
| `--ff-motion-fast` | `120ms` | 按钮按压、表格行 hover |
| `--ff-motion-base` | `180ms` | 菜单、小状态变化 |
| `--ff-motion-panel` | `260ms` | 抽屉、sheet、路由切换 |
| `--ff-motion-feature` | `420ms` | Dashboard 首次图表入场 |

### 缓动 Token

- 入场：`cubic-bezier(0.16, 1, 0.3, 1)`
- 离场：`cubic-bezier(0.7, 0, 0.84, 0)`
- 按压：`cubic-bezier(0.2, 0.8, 0.2, 1)`

### 动效规则

- 只动画 `transform` 和 `opacity`，避免动画 `width`、`height`、`top`、`left`。
- 页面切换使用 12-16px 方向位移 + 透明度变化。
- Dashboard 面板分组入场，每个元素间隔 30-45ms。
- 按钮按下缩放到 `0.97`，松开立即回弹。
- 表格行 hover 和 focus 时显示左侧能量条。
- 抽屉从操作源方向进入，并带遮罩。
- 图表首次进入可以绘制数据，但关闭动画后仍必须可读。
- 必须支持 `prefers-reduced-motion`，降低路由、图表和列表 stagger 动效。

## 交互规则

- 所有异步按钮都有 loading 和 disabled 状态。
- 危险操作需要确认，能撤销的操作优先提供撤销。
- 表单错误显示在字段附近，不能只靠颜色表达。
- 空状态提供明确下一步操作。
- 搜索和筛选在合理场景下保留状态。
- Toast 只报告结果，不抢焦点。
- 只有图标的按钮必须有 tooltip 和可访问标签。
- 表格必须统一 loading、empty、error、pagination 状态。
- 聊天必须显示发送中、已发送、失败、重连中和未读状态。

## 页面重构方案

### 登录页

概念：训练入口闸机。

- 背景使用深色健身房空间、器械剪影、橡胶地面纹理或训练网格。
- 会员、教练、管理员三种身份入口明确区分。
- 身份切换有空间位移，不只是替换文字。
- 登录错误既有字段提示，也有结果反馈。
- 提交时按钮进入 loading，并阻止重复提交。

### 后台布局

概念：运营指挥外壳。

- 左侧导航更紧凑、更硬朗，按 Overview、Members、Courses、Facilities、Training、Operations 分组。
- 当前导航项使用能量条、图标高亮和文字权重表达。
- 用户区展示角色、在线状态和退出操作。
- 所有后台子页面使用一致的路由切换动效。

### Dashboard

概念：健身房控制室。

- 首屏呈现实时运营指标：会员、课程、器械、客流、反馈、待处理任务。
- 使用大号等宽数字和短标签。
- 加入客流热力、待处理报修、课程利用率、今日排课。
- 图表颜色跟随 ForgeFit token。

### 会员管理

- 用 `FilterBar` 统一搜索、卡状态、会员类型、日期筛选。
- 用 `ProTable` 统一紧凑表格、固定操作列和会员身份单元格。
- 详情、编辑、新增使用 `DrawerForm`。
- 会员状态、卡状态使用 `StatusBadge`。

### 会员卡和钱包

- 卡片可以借鉴门禁会员卡视觉，但信息结构仍保持管理效率。
- 续费、挂失、充值都要有确认和结果反馈。
- 金额、次数、有效期使用等宽数字并右对齐。

### 课程管理

- 后台课程页使用紧凑表格、容量条和排课状态。
- 会员选课页使用更视觉化的课程卡，展示时间、教练、强度、容量和报名状态。
- 排课页尽量呈现为周视图或时间板。
- 报名页突出满员、取消、冲突、待处理等风险状态。

### 教练工作台

- 教练端像每日训练安排驾驶舱。
- 展示待处理预约、即将开始课程、会员上下文、聊天入口。
- 同意和拒绝操作必须有即时反馈。

### 训练计划和日志

- 训练计划使用按天排列的训练 lane、动作块、肌群 badge、组数次数和完成进度。
- 训练日志展示强度、时长、热量、感受和趋势。
- 打卡完成要有短促明确的完成反馈。

### 动作库

- 动作库不使用普通列表，应像训练素材库。
- 筛选项包括肌群、器械、难度、关键词。
- 动作项展示目标肌群、器械、难度和替代动作。
- 媒体位必须固定比例，即使没有图片也不引发布局跳动。

### 器械模块

- 器械管理重构为资产运营面板。
- 状态区分正常、维护中、待维修、停用。
- 报修流程使用分步表单，包含严重程度、位置、图片、描述。
- 器械详情抽屉展示维护历史和当前状态。

### 健康中心

- 健康页面使用体测仪表、饮食环、趋势图和照片进度。
- 健康模块使用更冷静的 ForgeFit 变体，青色和绿色多于橙色。
- 大指标必须显示单位和最近更新时间。

### 聊天

- 聊天页使用联系人栏、对话区、上下文侧栏。
- 在线、输入中、重连中、发送失败、未读状态都要可见。
- 消息气泡避免过度大圆角，用角色和对齐区分。
- 发送动作即时响应，失败后可重试。

### 客流热力

概念：全站视觉记忆点。

- 展示健身房区域、容量、实时人数和拥挤等级。
- 热力块刷新时分区点亮。
- 颜色从绿、黄、橙到红表达拥挤程度。
- 时间切片支持实时、30 分钟、1 小时、高峰对比。

### 错误和空状态

- 404 使用同一套视觉语言，并提供按角色返回的操作。
- 空状态使用功能型图形或结构化图标面板，不使用通用装饰插画。
- 错误状态必须提供恢复路径。

## 验证方式

最低验证要求：

- 执行 `npm run build`。
- 浏览器烟测登录、Dashboard、会员列表、课程排期、器械管理、训练计划、健康中心、聊天、客流热力。
- 检查桌面、平板、移动端截图。
- 抽查登录、侧栏、表格操作、弹窗、表单的键盘操作。
- 抽查低动效模式。
- 检查主文本、按钮、badge、错误提示的对比度。

## 验收标准

- 所有主要页面属于同一个 ForgeFit OS 视觉系统。
- 旧的 Apple glass 和浅色 slate 不再是主界面语言。
- 关键页面没有明显混搭风格。
- 组件使用语义 token，不重复散落裸色值。
- 后台表格、会员流程、表单、弹窗、聊天和图表都有一致的 loading、empty、error、success 状态。
- 路由、面板、按钮、图表和表格交互使用共享动效系统。
- 移动端可读、可操作，不出现明显重叠。
- 主要移动端触控目标不小于 44px。
- 应用可以成功构建。

## 风险和缓解

- **范围过大**：全站重构容易失控。缓解方式是先落地地基和壳层，再按页面组推进。
- **Element Plus 默认风格泄漏**：原生样式容易破坏统一性。缓解方式是全局主题覆盖和包装组件。
- **深色模式对比不足**：能量色使用不当会影响阅读。缓解方式是建立前景 token 并做对比检查。
- **动效过载**：冲击力可能变成干扰。缓解方式是统一动效 token，只保留有意义的动效。
- **移动端表格密度**：后台数据在小屏容易溢出。缓解方式是表格容器横滚、关键列固定、必要时提供移动摘要视图。
