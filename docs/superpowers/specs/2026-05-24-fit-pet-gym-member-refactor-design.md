# Fit-Pet Gym 会员端重构设计文档

## 项目概述

将现有健身房管理系统重构为 **Fit-Pet Gym**：桌面优先、全中文、2D Q 版游戏视觉、音效活泼但不过度。

### 核心方向
- 把现有健身系统压缩成纯会员端体验
- 用"反焦虑 + 游戏化 + Q 弹可爱动效"重塑体验
- 删除管理端、教练端，只保留会员端公开体验

---

## 技术路线

| 层 | 选择 | 说明 |
|---|---|---|
| 前端 | Next.js + React + TypeScript | 重建，替换现有 Vue/Vite |
| 动效 | Framer Motion + CSS/SVG | 2D Q 版，不引入游戏引擎 |
| 后端 | 继续使用现有 Spring Boot REST/JWT | 删端不删数据 |
| 认证 | JWT | 前端保存 token，游客不调受保护接口 |
| 前后端分工 | Next 直接调 Spring REST | 不引入 Next BFF |

## 游戏系统设计

### 游戏循环

| 周期 | 内容 |
|---|---|
| 每日循环 | 训练打卡 → 宠物喂养 → 每日任务 → 每日扭蛋 |
| 每周循环 | 匿名聚合 BOSS → 宿敌挑战（上周自己的匿名数据）→ 周奖励结算 |
| 长期循环 | 宠物进化 → 肌肉领地成长 → 成就 → 称号 → 收藏 |

### 宠物系统
- 三选一初始宠
- 动作状态：待机、开心、投喂、训练、攻击/讨伐、胜利、睡觉
- 不训练时温和提醒，不掉级惩罚
- 日系绘本/贴纸风格：毛绒感、线稿、围巾、表情细节

### BOSS 系统
- 常见高热量食品 Q 版造型：草莓甜甜圈、熔岩汉堡、黑糖奶茶等
- 匿名聚合全店进度，无公开排行榜
- BOSS 动画需符合食品形象

### 奖励体系
- 以虚拟奖励为主，不做现实权益核销
- 第一版不做真实设备同步、不做公开排行榜、不做好友社交

### 多人/社交
- 匿名聚合处理：全店共同目标，无公开排名压力

## 数据层设计

### 新增 Spring Boot 游戏化接口（统一前缀 `/game`）

| 端点 | 说明 |
|---|---|
| `/game/profile` | 会员游戏档案、等级、经验、当前宠物 |
| `/game/pets` | 宠物选择、状态、喂养、进化、装饰 |
| `/game/tasks` | 每日任务、完成状态、奖励领取 |
| `/game/boss` | 当前周 BOSS、匿名总进度、个人贡献 |
| `/game/gacha` | 每日扭蛋、Buff、虚拟奖励记录 |
| `/game/achievements` | 成就、徽章、称号、背包 |
| `/game/rivals` | 宿敌（上周自己的匿名挑战数据）|
| `/game/muscle-map` | 按训练日志 + 动作肌群计算部位活跃度 |

### 新增数据表
- `gym_game_profile`
- `gym_game_pet`
- `gym_game_task`
- `gym_game_reward`
- `gym_game_boss`
- `gym_game_boss_contribution`
- `gym_game_gacha_log`
- `gym_game_achievement`
- `gym_game_member_achievement`

### 教练/课程游戏化字段
- 力量、耐力、技巧、亲和、强度、稀有度
- 卡面素材、推荐标签
- 通过 SQL/配置文件初始化

### 保留并迁移的现有表
会员、课程、教练、排课、训练、动作、健康、饮食、体测、人流、会员卡

**注意：迁移前需备份上述表。新增游戏表不清空现有业务表。**

## 音效策略

- 桌面浏览器受自动播放限制
- 设计为"首次用户交互后启用音效"
- 提供音效开关入口
- 低动效偏好时减少动画

---

## 视觉风格

- 全中文文案
- 玩法名中文化：讨伐小队、每日扭蛋、宿敌挑战、饮食炼金、机甲扫描
- 减少文字内容，加强交互细节
- 动画夸张但不失控，Q 弹可爱风格
- 宠物精致日系绘本风，避免塑料/廉价感
- BOSS 为高热量食品 Q 版，精致不草率
- 加载动画：进度条 + 跳动宠物 + 飞入碎片（进入游戏感）

## 测试计划

### 后端测试
- 会员注册/登录、游客无权限访问保护
- admin/coach 登录不可用
- 游戏档案初始化、宠物选择、每日任务刷新

### 前端测试

- 桌面主流程：游客进入 → 注册/登录 → 选宠物 → 打卡 → 喂养 → 抽扭蛋 → 报名课程 → 查看成就
- 桌面优先布局，基本移动适配检查
- 音效首次互动后启用，提供关闭入口
- 低动效偏好时减少动画

- 迁移前备份现有数据
- 新增游戏表不清空现有业务表
- 课程/教练游戏属性通过 SQL/配置文件初始化

## 假设与约束

- 现有数据库保留并迁移，不做清库重建
- 管理端和教练端作为公开产品端彻底删除，相关数据可继续服务会员端
- 运营配置（课程 BOSS 奖励等）走 SQL/配置文件
- 第一版不做：真实设备同步、现实奖励核销、公开排行榜、好友社交
- 设计文档输出为仓库 Markdown
